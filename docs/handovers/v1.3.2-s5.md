## H105 decision

Retain `sqlite3` 3.9.1 in the release lockfile. The existing `^3.9.1` constraint
permits 3.9.2, but this task changes neither dependency file.

The [official package changelog](https://pub.dev/packages/sqlite3/changelog),
checked 2026-11-28, reports native finalizer and NUL-containing SQL fixes in
3.9.2 and an encrypted native library upgrade from SQLite3 Multiple Ciphers
2.6.1 to 2.7.0. This is relevant reliability work, but requires explicit old
ciphertext compatibility evidence before adoption.

Current pinned Linux `test/data/app_database_test.dart` passed in the focused
run. It checks encrypted bytes, wrong/missing-key refusal without modifying the
file, reopen, encrypted migration backup and snapshot reopen. It does not prove
that a file written with 3.9.1 opens with 3.9.2 on Linux and Android arm64.
Those cross-version checks, native Android encryption verification, and any
candidate encrypted-library evaluation remain missing. Retaining 3.9.1 meets
the plan's conditional dependency acceptance without an unverified upgrade.
