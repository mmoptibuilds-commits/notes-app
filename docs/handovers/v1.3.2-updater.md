## A23 release safeguards

The scoped suite passed the Linux editor save barrier, the Android release
certificate pin, manifest verification, and the unencrypted JSON export
confirmation. GitHub reports the manual release build workflow active. The
effective `main` rules deny deletion and non-fast-forward updates. The legacy
branch-protection API reports no rule, and the effective rules do not require
a pull request or status checks. The base commit `d2e6c67` passed
[CI](https://github.com/mmoptibuilds-commits/notes-app/actions/runs/46071764589).
Current stable is [v1.3.1](https://github.com/mmoptibuilds-commits/notes-app/releases/tag/v1.3.1),
and the tracked last distributed build is `20261127`.

Independent review, release package checks, and CI must cover the integrated
candidate. Owner checks include the installed Android versionCode, recovery
from an independent offline signing-key backup, production signing and
verification, release approval, and the actual updater from v1.3.1 after
publication. The documented two manifest key backups are both online. S3
did not exercise owner devices or production signing.

The coordinator closed the replay-watermark atomicity gap: the settings-backed
store reads the persisted mark and compares/advances version and build in one
writer transaction, so app windows with stale settings caches cannot lower or
mix the mark. A synthetic SQLite-trigger regression proves that a failure on
the build write rolls back the version write as well; a two-connection test
proves that a second cache rejects an older release
(`test/update/update_state_test.dart`).

The follow-up review identified a compatibility case left by 1.3.1's
version-then-build writes: a failed second write can leave only the version
watermark. The final candidate keeps whichever floor is present (semantic
version or build number) until an accepted manifest repairs the pair. The
regression test covers both partial states. A version-only legacy mark cannot
preserve a same-version build floor that never reached disk; the candidate
preserves the known semantic-version floor and repairs the pair on acceptance.
