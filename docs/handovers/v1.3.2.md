## Timing failure investigation

The v1.3.1 baseline at `d2e6c67b626ee2fb36d2d717d2f25c9a8f335c60` passed the
full suite with the default Dart test-runner concurrency: 1,668 passed, 7
skipped, 0 failures in 3m19s (`/tmp/notes-v132-v131-full.log`). The pre-fix
v1.3.2 candidate had two default-concurrency runs: 1,752 passed / 7 skipped
with one reverse-sync assertion failure, then 1,751 passed / 7 skipped with
that failure plus the healthy loopback request timeout. The affected pair
passed 37/37 together and the candidate passed 1,753 / 7 with one worker.
These comparisons used the same Flutter 3.50.0 host and default concurrency.
The `SyncService` and cloud HTTP client sources match v1.3.1. Candidate changes
also touch shared database and peer code; inspection and reproductions did not
trace the timing failures to those changes, and no corresponding product
defect was reproduced.

- Reverse sync: the test slept exactly 100 ms after a completed outbound call,
  then asserted that the peer had already applied the follow-up note while
  the receiving service could still be finishing bookkeeping. This was a
  scheduling assumption in the test, not a sync regression. The test now waits
  for both services to become idle using its existing bounded `_quiet` helper
  and checks both the follow-up result and idle state. It does not serialize
  tests or extend a product timeout. The earlier logs are
  `/tmp/notes-v132-final4-independent-suite.log`,
  `/tmp/notes-v132-final4-independent-suite-rerun.log`, and
  `/tmp/notes-v132-final4-independent-serial-suite.log`.
- Loopback HTTP: the test used the same 30 ms deadline for its intentionally
  stalled request and its healthy local positive-control request. The failing
  stack was at the healthy response assertion (`matrix_hostile_test.dart:43`);
  a host scheduling delay under full-suite load can exceed 30 ms even though
  the server responds. This is an overly tight test deadline, not a cloud HTTP
  product regression. The test now gives that probe a finite 1 s deadline;
  the stalled request still has to time out and the following healthy response
  must succeed. The targeted suite passed 37/37 and the final default-
  concurrency candidate suite passed 1,753 / 7.

Disposition: test scheduling/deadline defects, no product defect reproduced,
and no candidate regression relative to the passing v1.3.1 baseline.
