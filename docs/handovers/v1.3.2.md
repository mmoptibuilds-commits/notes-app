The first independent review of `0afe511` found seven findings (one critical,
five high and one medium). Commit `59ddafe` addresses simultaneous first-run
key and LAN identity creation, duplicate/discarded draft retries, note purge
between recovery and save, latest-text serialization failure, empty SQLite
files counted as backups, rollback ordering/export loss, and the reversed
release-notes link. The reviewer reproduced the key and editor failures with
synthetic data.

A fresh review of `feefdc0` then reproduced six high-priority edge cases. The
fixes in `dbf8c4f` reload the newest draft after acquiring its lease, keep
serialization fallback conditional on a still-pending row, save live-editor
retries under a new ID after permanent deletion, distinguish an unavailable
draft from Trash, retain the newly published import backup under the directory
lock despite older files having future mtimes, and continue closed-editor
retries with capped backoff until a draft is durable. Independent reproductions
were converted to synthetic tracked regression tests.

The follow-up review of `0210691` found two more issues. Commit `c7e1816`
reads and advances the updater replay mark from persisted settings in one
transaction, preventing a stale second window from lowering it; it also puts
latest-draft lookup inside the lease cleanup guard so a read failure releases
the lock. A stale-cache two-connection test and a fail-once draft-read test
cover these cases.
