## Objective

Prevent silent loss of notes, unsaved drafts, sync metadata and recoverable database backups. Preserve existing Android/Linux update trust and compatibility. No feature expansion or protocol rewrite. Cloud reliability work outside the quarantine boundary remains in v1.3.3.

## Work sequence

1. Coordinator fetches main, inspects current source and existing tests, records baseline and exact task ownership. Use notes-worktrees, notes-data-integrity, notes-regression, notes-handoff and notes-release as applicable.
2. Reproduce each reported failure with synthetic data in a disposable directory/worktree. Run independent packages in parallel only when file ownership does not overlap. One coordinator owns migrations, shared repository interfaces, dependency locks and integration. If S1 and S2 require the same persistence files, define the interface first or serialize the changes.
3. Implement smallest fixes and focused tests. If a finding is disproven or already fixed, record evidence and do not add unnecessary code. Keep production cloud, private notes, keys and existing checkout untouched.
4. Integrate onto the current release branch in dependency order; run full checks and independent exact-SHA review. Check upgrade from released databases, failure injection, crash/restart, old peers, package and signed-update compatibility.
5. Finish all autonomous work before collecting physical checks in one report. Use laptop and Android ADB only with permission; test fixtures not real notes. No production changes without owner approval.
6. Update documentation and version only under approved release procedure. Select increasing build number from last distributed build and installed version codes. Follow RELEASE.md, candidate signing, checksums, signed manifest and owner approval gates. Verify actual updater from v1.3.1 after publication; do not start v1.3.3 until stable release gate passes.

## Release gate

No unresolved critical data-loss, security, unsafe updater or migration defect within scope. Recovery tests prove preserved drafts and backups. Full relevant checks green, review independent, remaining limitations recorded. Owner approves merge, deployment if needed, signing, publication and installations. A date is not a reason to skip any gate.

## Explicitly out of scope

Live editing, new workspaces, CLI/MCP/chat, LAN removal, platforms, reminders, widgets, major UX redesign, new paid infrastructure, general dependency upgrades, broad refactors and unrelated cloud reliability fixes. If new critical findings appear, stop and document them for scoped owner decision rather than silently expand the release.
